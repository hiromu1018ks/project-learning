# project-learning スキル設計書

- 日付: 2026-10-03
- 状態: 設計対話にて承認(解説レベルの厳格化についての修正指示を反映済み)
- 次のステップ: ユーザーによる設計書レビュー → `/skill-creator:skill-creator` による実装

## 1. 背景と目的

ユーザーは superpowers スキル群を使い、設計 → 実装計画 → 実装という流れで開発を進める。
しかし AI が成果物を生成するため、**「動いたコード」の中身と理由をユーザーが理解しないまま開発が進みやすい**。

本スキルは、superpowers が作った設計書・計画書・実装コードを入力として、
初学者向けの学習ドキュメント(Markdown + HTML)を生成する。
単なる要約ではなく、「なぜこの設計になったのか」「コードの各部分が何をしているのか」を、
背景から順に理解できる教材へと再構成する。

実行は常に手動(設計 → 計画 → 実装の完了後、ユーザーの任意タイミング)であり、
superpowers の開発フローには自動組み込みしない。

## 2. 目標と非目標

### 目標

- superpowers 成果物を教材化する md を生成し、同梱スクリプトで html と一覧ページに変換する
- `LEARNING_STATE.md` で執筆状況を管理し、重複生成を防ぎつつ教材を蓄積する
- GitHub で公開し、`npx skills add <owner>/project-learning` で誰でも使えるようにする
- 教材は日本語・初学者向けとする(後述の解説レベル制約に厳格に従う)

### 非目標(YAGNI)

以下は作らない: 検索機能、多言語化、テーマ切り替え、WEB ホスティング・CI、
実装完了後の自動実行、PDF 出力、md/html 以外の出力形式。
教材はローカルのブラウザで `index.html` を開いて読む前提とする。

## 3. 主要な決定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| スキル名 | `project-learning` | リポジトリ名と統一(ユーザー希望) |
| 配布形態 | GitHub 公開 + `npx skills add` | ユーザー希望。npx 経由なら Node が必ずある |
| 出力形式 | Markdown(原稿)+ HTML(生成)+ index.html | ユーザー希望「md も html も作る」 |
| HTML 生成方式 | スキル同梱の変換スクリプト(案A) | 執筆の手間・トークン半減、品質一定、依存ゼロ |
| 実行タイミング | 手動のみ | 任意タイミングでの学習という元要件を維持 |
| 教材の言語 | 日本語 | ユーザーの学習言語 |
| ライセンス | リポジトリは MIT、marked は同梱時にライセンス表示を保持 | MIT は同梱配布を許諾 |

## 4. 全体構成

### 配布リポジトリ(GitHub で公開)

```
project-learning/              ← リポジトリ本体
├── README.md                  ← インストール手順・使い方(日本語)
├── LICENSE                    ← MIT
├── docs/superpowers/specs/    ← 本設計書など
└── project-learning/          ← スキル本体(npx skills add でインストールされる)
    ├── SKILL.md               ← スキルの手順書
    ├── scripts/
    │   └── build-html.mjs     ← md → html 変換スクリプト(Node, 依存ゼロ)
    └── assets/
        ├── marked.min.js      ← Markdown 変換エンジン(MIT, 同梱)
        └── style.css          ← 教材ページのデザイン
```

### 実行対象プロジェクト(学習したい開発を行った任意のプロジェクト)

```
├── docs/superpowers/...       ← superpowers が作った設計書・計画書(入力)
├── LEARNING_STATE.md          ← 学習進捗の記録(スキルが管理)
└── docs/learning/             ← 成果物
    ├── 01-xxxx.md             ← Claude が執筆する元原稿
    ├── 01-xxxx.html           ← スクリプトが生成
    ├── (style.css)             ← スキル側 assets のものを各 html に埋め込むため、ここには置かない
    └── index.html             ← 教材一覧ページ(自動生成)
```

## 5. スキルの動作フロー

ユーザーが学習対象プロジェクトで `/project-learning` を実行したとき:

1. **環境確認** — `node --version` を実行。Node が無ければインストール案内を表示して中断
2. **状態の確認** — `LEARNING_STATE.md` を読み執筆済みテーマを把握(無ければ新規として初期化)
3. **入力の発見** — `docs/superpowers/` 配下の設計書・計画書と、対応する実装コードを探す
4. **執筆計画の提案と確認** — 未執筆テーマを列挙し「今回はこのテーマを書きます」と提示してユーザーの確認を得る
5. **Markdown の執筆** — セクション 6 の構成と解説レベル制約に従い `docs/learning/NN-スラッグ.md` を執筆
6. **HTML の生成** — `node <スキルのscripts>/build-html.mjs docs/learning/` を実行し、
   全 md から html と index.html を再生成(html は常に入れ替える派生物とする)
7. **状態の更新** — `LEARNING_STATE.md` に執筆済みテーマ・日時・今後の題材を記録

## 6. 学習ドキュメントの仕様

### ファイル命名

- `01-テーマのスラッグ.md` のように連番付き(半角英数ハイフン推奨、並び順の安定のため)
- 1 枚 = 1 テーマ(1 つの設計書と、その計画・実装のセット)

### 本文の構成(テンプレート)

1. 今回何を作ったのか
2. なぜその機能が必要なのか
3. 全体の設計
4. 設計上の重要な判断
5. 実装までの計画
6. 実際のコード構成
7. コードがどのように動くのか
8. 使用している技術・パターンの解説
9. 設計と実装の対応関係
10. 初学者が覚えておくべきポイント
11. ことばのまとめ(その回で登場した用語の簡単な辞書)

### 解説レベル制約(最重要・厳守)

対象読者は「プログラミング経験ほぼゼロの初学者」。以下を SKILL.md に強制事項として書く:

1. 専門用語は初出時に必ず平易な定義を併記する(例: 「リポジトリ(= 変更履歴つきのプロジェクト保管場所)」)
2. 例え話(郵便・料理などをプログラミングにたとえる説明)は使わない。読者に余計な読み替えを強いるため。構造・流れ・比較は、図や表で視覚的に示す
3. 1 文は 40 文字を目安とし、1 文 1 情報を守る
4. コードは 3〜10 行程度の小さい断片に分け、直後に各断片が「何をしているか」を説明する
5. 説明の順序は「何が起きるか → なぜそうなるか → どこで使われているか」の順
6. 読者に要求する前提知識は「ファイルとフォルダ」「ブラウザでページを開く」までとし、
   それ以上の概念は教材の中で補足する
7. 深い内部動作・最適化・歴史的経緯は原則省略し、必要な場合のみ「ここはまだ理解しなくてよい」枠で示す
8. 文体は平易な言葉を選び、文字数の多い漢語よりも日常語を優先する
9. 処理の流れ・全体構造・対応関係の説明では、文章だけに頼らず図や表を積極的に使う。
   図はコードブロック内に描くテキスト図(文字と罫線で描く図)、表は Markdown の表形式とし、
   どちらも変換スクリプト側の追加対応なしで HTML 化できる形式に限る

## 7. LEARNING_STATE.md の仕様

- 場所: 実行対象プロジェクトのルート
- 形式: Markdown(人が読んでも分かる構造)
- 内容:
  - 対象となった設計書・計画書・実装コードのパス一覧
  - 執筆済みドキュメント一覧(ファイル名・執筆日時・対象とした設計書)
  - 今後追加すべき解説項目(未執筆テーマ)
  - メモ(任意)
- 本ファイルはスキルだけが読み書きする状態管理の唯一のファイルとする

## 8. build-html.mjs の仕様

- 実行環境: Node 18 以上。npm インストール不要(変換エンジン marked を `assets/` に同梱)
- 起動: `node <スキルのパス>/scripts/build-html.mjs <docs/learning のパス>`
- 処理:
  1. 対象ディレクトリの `*.md` を列挙(frontmatter があれば読み飛ばし)
  2. 各 md を HTML に変換し、`assets/style.css` を埋め込んだ単一ファイルの html を同名で出力
  3. `index.html` を再生成(連番順の一覧、各ドキュメントへの相対リンク、執筆日時)
  4. 変換は常に全再生成とし、md 以外の html はすべて作り直す(派生物の陳腐化を防ぐ)
- 出力メッセージは日本語で、生成ファイル数を報告して終了する

## 9. エラー処理

| 状況 | 挙動 |
|---|---|
| superpowers の成果物が見つからない | 「教材化できる設計書・計画書がありません」と報告して終了(推測で作らない) |
| `LEARNING_STATE.md` が壊れている/形式が違う | バックアップを作成してから初期化し、ユーザーに通知 |
| Node がインストールされていない | 手順 1 で検知し、インストール案内を表示して中断 |
| md に壊れた記法があり変換できない | そのファイルをスキップし、ファイル名と理由を報告(他は処理を続行) |

## 10. テスト方針

1. **スクリプト単体**: サンプル md(見出し・コードブロック・箇条書きを含む)を変換し、
   正しい html・index.html が出ること、既存 html が全再生成されることを確認
2. **全体の試行**: ダミープロジェクト(設計書・計画書・コードを用意)でスキルを 1 周実行し、
   LEARNING_STATE.md の更新と再実行時の重複排除を確認
3. **配布確認**: GitHub に push 後、`npx skills add` でインストールできることを実環境で確認

## 11. 実装と公開の進め方

- 実装は `/skill-creator:skill-creator` を使用する(ユーザー指示による。writing-plans は使わない)
- 実装完了後、リポジトリを GitHub に公開(public)し、README に `npx skills add` の手順を記載する
- `marked.min.js` のライセンス表示は同梱時に保持する
