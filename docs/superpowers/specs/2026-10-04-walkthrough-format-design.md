# project-learning スキル: walkthrough 形式への転換 設計書

- 日付: 2026-10-04
- 状態: 設計対話にて承認(前半: 動作フローと章の構成 / 後半: 進捗管理・点検・周辺更新)
- 次のステップ: ユーザーによる設計書レビュー → `/skill-creator:skill-creator` による実装

## 1. 背景と目的

初版のスキル(2026-10-03 設計)は「1冊 = 1テーマ」で、
背景 → 設計 → 実装 → まとめ の11項目テンプレートで教材を書く方式だった。

その後、ユーザーは java-test プロジェクトで walkthrough 形式の解説書
(`docs/learning/walkthrough/` 以下 12 章)を別セッションで直接執筆した。
これは「利用者の操作を1つ選び、その操作で動くコードを実行の順番に読む」形式で、
学習体験として優れていた。

本設計は、スキルの出力形式をこの walkthrough 形式へ**全面切り替え**するものである。
旧テンプレート(テーマ単位の解説)は廃止する。12 章の実物から暗黙の作り方を取り出し、
SKILL.md として明文化するのが本作業の核心である。

参考にした際の判断: 実物の制約(35 行コードを1ブロックで載せる等)はそのまま
引き継がず、この形式でのベストをゼロベースで設計する(ユーザー指示)。

## 2. 目標と非目標

### 目標

- SKILL.md を walkthrough 形式の手順書として全面改訂する(ルールは1枚にまとめる)
- 章を複数回に分けて執筆できるよう、章リストと「再開地点」を LEARNING_STATE.md で管理する
- README を新形式に合わせて更新する

### 非目標(YAGNI)

- build-html.mjs・style.css の変更(現行のまま chapter 形式を処理できる)
- 旧テンプレートとの両対応(全面切り替えのため)
- 既に書かれた java-test の教材(概説2冊・walkthrough 12章)の移行・修正
- 検索・多言語化・テーマ切り替え・PDF 出力(初版設計の非目標を引き継ぐ)

## 3. 決定事項

| 項目 | 決定 | 理由 |
|---|---|---|
| 出力形式 | walkthrough 形式に全面切り替え | ユーザー希望。形式の迷いをなくす |
| ルールの置き場所 | SKILL.md 1枚にまとめる | 執筆に必要なルールは毎回すべて使うため、分離しても毎回読むことになる |
| 章の単位 | 利用者が行う操作1つ | 操作起点でコードの実行順を追うのが本形式の核 |
| 「なぜ」の扱い | 専用セクションを設けず、疑問が湧く箇所に短く添える | 実物で機能していた方式。設計書はその材料として補助的に使う |
| コード断片の上限 | 10 行以内+行ごとの表 | 実物は 35 行の例外があったが、既存スキルで実績のある規律を維持する |
| 図とコードの区別 | 図は `text` タグ、コードは言語タグ(java など) | 点検コマンドで両者を機械的に区別できるようにするため |
| 設計書・計画書の扱い | 必須入力から「なぜ」の材料に格下げ | 操作の列挙はコードから行うため。無くても執筆できる |
| 実装方法 | `/skill-creator:skill-creator` | 前回初版と同じ(ユーザー指定)。writing-plans は使わない |

## 4. スキルの動作フロー

```
環境確認 → 進捗確認 → 操作の列挙 → 章リストの提案と承認 → 章の執筆 → HTML 生成 → 進捗の更新
```

1. **環境確認** — `node --version`(初版と同じ。無ければ案内して中断)
2. **進捗の確認** — `LEARNING_STATE.md` を読む(無ければ新規、旧形式・壊れていれば
   バックアップ後に新形式で初期化して通知)
3. **操作の列挙** — 実装コードを読み、「利用者が行える操作」を列挙する。
   出典はメニュー項目・コマンド一覧・画面・ルーティングなど利用者から見える挙動の単位。
   設計書・計画書があれば「なぜ」の材料として読むが、無くても進めてよい。
   操作が1つも見つからない対象(ライブラリなど)は「代表的な使い方1つ」を1操作とみなす
4. **章リストの提案と承認** — 初回は 章0(導入)+ 操作ごとの章リストを番号付きで提案し、
   ユーザーの承認を得てから LEARNING_STATE.md に記録する。
   2回目以降は未執筆の章から「今回はこの章を書きます」と提案する。
   **1回の実行で書くのは 1 章(大きな操作は前後半に分けても 2 章まで)**。
   開発が進んで操作が増えていた場合は、章リストへの追加を提案して承認を得る
5. **章の執筆** — 続きの章では、まず前章の追跡の最終 Step を読み、
   LEARNING_STATE.md の再開地点を確認してから書き始める
6. **HTML の生成** — `node <スキルのディレクトリ>/scripts/build-html.mjs docs/learning`(初版と同じ)
7. **進捗の更新** — 章リストの執筆日と、次章の「再開地点」を LEARNING_STATE.md に書き込む

## 5. 解説書(章)の仕様

### 5.1 ファイルの命名と配置

- 出力先は `docs/learning/` 直下。サブディレクトリは作らない
- ファイル名は `NN-スラッグ.md`(2桁の章番号+短いローマ字のスラッグ。例: `01-kidou.md`)
- 章番号とファイル名の 2 桁は一致させる
- 冒頭の frontmatter(title・date)は初版と同じ(変換スクリプトが一覧に使う)

### 5.2 章0(初回に1回だけ作る導入)

| 内容 | 説明すること |
|---|---|
| この解説書の読み方 | 操作を選び、その操作で動くコードを実行順に読む形式であること。「プログラムはファイルを上から順に読んでも動きが分からない」ため、章と節が移動の順番どおりに並んでいること |
| 各章の構成 | 4 パート(下記)の紹介と、章どうしが前章の続きから始まること |
| コードの載せ方 | 断片+行ごとの表であること。説明済みのものは「(章Nで説明済み)」とだけ書くこと |
| 頻出用語の定義表 | 全章を通じて頻出する用語の表 |
| プロジェクトの形 | フォルダ構造の `text` 図 |

### 5.3 章1以降の構成(4 パート固定)

章の冒頭に必ず **「章 N-1 の Step X の直後から始まります」** の1行を置く。

```
# 章3 一覧の表示
(章2 の Step 7 で 2 が入力された直後から始まります)

## 1. この章で追う操作
## 2. 流れの全体図
## 3. 実行の追跡
## 4. この章で登場したファイル
```

| パート | 内容 |
|---|---|
| 1. この章で追う操作 | 利用者の操作を番号付きで並べる(例: ①メニューで 2 を入力 ②一覧が出る) |
| 2. 流れの全体図 | 呼び出しのつながりを `text` 図で示す。分岐がある場合は、本章で追う道と「(他章で追う)」という印を明示する |
| 3. 実行の追跡 | Step 1, 2, ... の順で。各 Step の型は「いま何をしているか(平易な文)→ コード断片(10 行以内+行ごとの表)→ なぜ(必要な箇所だけ)」 |
| 4. この章で登場したファイル | 表: ファイルパス \| この章で分かったこと |

### 5.4 コードの載せ方

- コードは実ファイルからそのままコピーする(手で書き換えない)
- 1 断片は **10 行以内**。直後に「行ごとのやっていること」の表を付ける
  (表の行番号は断片の中での番号とする)
- import 文など説明対象にならない定型は省略し、「(import 6行)」のように1行で示してよい
- クラス全体を見せたい場合は、断片を分割して順番に並べる(1 ブロックで丸ごと載せない)
- 過去の章で説明済みのメソッドは「(章Nで説明済み)」とだけ書く
- コードには言語タグ(java など)を付ける

### 5.5 図と表

- 図はコードブロック内のテキスト図で、必ず `text` タグを付ける
- 図は行数制約の対象外とする(見やすさを優先する)
- 対応関係・比較は文章より表を優先する

### 5.6 「なぜ」の扱い

- 専用セクションを作らない。追跡の途中で「なぜこうなっているのか」という疑問が
  自然に湧く箇所で、短く添える
- 材料は設計書・計画書・git log の判断記録。無い場合は推測で理由を作らない

### 5.7 章の分割

1 章を書き進めた結果、明らかに長くなりすぎると判断した場合は、
追跡の自然な区切りで章を分け、以降の章番号を繰り下げる。
章リストと LEARNING_STATE.md を更新し、ユーザーに報告する。

## 6. 解説レベル制約(初版から引き継ぐ・最重要)

1. 専門用語は初出時に必ず平易な定義を併記する
2. 例え話は使わない。構造・流れ・比較は図や表で示す
3. 1 文は 40 文字を目安に、1 文 1 情報
4. 説明の順序は「何が起きるか → なぜそうなるか → どこで使われているか」
5. 前提知識は「ファイルとフォルダ」「ブラウザでページを開く」まで
6. 深い内部動作・最適化・歴史的経緯は原則省略(必要時のみ「ここはまだ理解しなくてよい」と断る)
7. 文体は日常語を優先する

## 7. 点検手順(章を書き終えるたびに実施)

| # | 確認すること | 方法 |
|---|---|---|
| 1 | コード断片が 10 行以内か | awk 点検(下記) |
| 2 | すべての断片の直後に「行ごとの表」があるか | 目視 |
| 3 | 図に `text` タグ、コードに言語タグが付いているか(無タグのブロックが無いか) | awk 点検(下記) |
| 4 | 章の冒頭に前章の再開地点が書かれているか | 目視 |
| 5 | パート1の操作手順が、パート3の追跡ですべて通過しているか | 目視 |
| 6 | 初出の専門用語に定義があるか | 目視 |

コード断片の行数点検(コードのみを数え、`text` 図と無タグを除外する):

```
awk '/^```/{if(f){if(t&&n>m)m=n;f=0}else{f=1;n=0;t=($0~/^```[a-zA-Z]/&&$0!~/^```(text|plain)/)?1:0}next} f{n++} END{print m+0}' docs/learning/*.md
```

出力が 10 を超えたら、超えている断片を処理のまとまりで分割する。

タグ規約の点検(無タグで開かれたブロックの個数。0 であれば規約どおり):

```
awk '/^```/{if(f){f=0}else{f=1;if($0!~/^```[a-zA-Z]/)u++}next} f{n++} END{print u+0}' docs/learning/*.md
```

(両コマンドとも 2026-10-04 に java-test の walkthrough 12 章で動作確認済み)

## 8. LEARNING_STATE.md の仕様(新形式)

```markdown
# 学習の進捗(project-learning)

## 対象の成果物
- 実装コード: (主な所在)
- 設計書・計画書: (「なぜ」の材料。なくても可)

## 章リスト(承認済み)
| 章番号 | 操作 | ファイル | 執筆日 |
|---|---|---|---|
| 0 | この解説書の読み方とプロジェクトの形 | 00-junbi.md | YYYY-MM-DD |
| 1 | (操作名) | (未執筆) | |

## 再開地点(次に書く章はここから始める)
- 章2 は「章1 の Step 5 で 1 が入力された直後」から

## メモ
- (次回に引き継ぎたいこと)
```

- 「再開地点」は章を書き終えるたびに必ず更新する(章間のつながりを保証する唯一の記録)
- 既存の LEARNING_STATE.md が旧形式(テーマ単位)だった場合は、バックアップを残して
  新形式で初期化し、ユーザーに通知する(既存教材のファイルはそのまま残す)

## 9. 変えるもの / 変えないもの

| ファイル | 扱い |
|---|---|
| project-learning/SKILL.md | 全面改訂(本設計の内容に従う)。description も walkthrough 形式を示す語に更新 |
| README.md | 出力物の説明を walkthrough 形式に書き換え |
| project-learning/scripts/build-html.mjs | 変更しない(連番ソート・frontmatter・相対リンク書き換え・一覧生成がそのまま使える) |
| project-learning/assets/ | 変更しない |
| tests/test-build-html.mjs | 変更しない(スクリプト不変のため) |
| evals/evals.json | 評価観点が変わるため、必要に応じて更新 |

## 10. エラー時の挙動

| 状況 | 挙動 |
|---|---|
| Node が無い | 案内を表示して中断(初版と同じ) |
| 実装コードが見つからない | 「教材化できる実装が見つかりません」と報告して終了(推測で作らない) |
| コードが読めず操作の候補を挙げられない | ユーザーに候補を尋ねてから進める(§4 の「操作が1つも見つからない対象」= ライブラリ等の扱いとは別の状況) |
| LEARNING_STATE.md が壊れている・旧形式 | バックアップを残して新形式で初期化し、通知 |
| md の変換に失敗 | スクリプトの報告を見て該当 md を修正し、再実行(初版と同じ) |

## 11. テスト方針

1. **点検コマンド**: `text` 図と 10 行超の java 断片を混ぜたサンプル md で、
   2 つの awk 点検が正しい値を返すことを確認
2. **全体の試行**: 操作のある小さなダミープロジェクトでスキルを 1 周し、
   章0・章1 が生成され、LEARNING_STATE.md に章リストと再開地点が記録されることを確認
3. **継続の試行**: 2 回目の実行で、続きの章が前章の再開地点からつながって書かれることを確認
